# FinGuardOps FDS 분석 화면 와이어프레임

## 0. 문서 경계

- 본 문서는 FDS 분석 담당자의 거래·사건 검토 업무 화면을 정의한다.
- 서비스 상태·성능·AI 비용은 `docs/01-requirements/platform-screen-wireframes.md`에서 정의한다.
- API·DB·상태 전이는 후속 설계 문서에서 확정한다.
- 이 문서는 요구사항 단계의 텍스트 와이어프레임이며, 구체적인 API 경로, DTO, Entity, DB 컬럼, 상태 전이와 픽셀 단위 디자인은 다루지 않는다.
- 화면에 표시하는 개인정보는 마스킹을 전제로 하며, 원문 노출을 전제로 작성하지 않는다.
- 참고 문서: `docs/00-overview/fds-service-scope.md`, `docs/01-requirements/fds-user-scenarios.md`, `docs/07-decisions/ADR-001-finguardops-positioning.md`

## 1. FDS 대시보드

### 사용자

FDS 분석 담당자

### 화면 목적

- 위험 거래와 사건 현황을 요약해서 파악한다.
- 우선 검토할 HIGH·CRITICAL 사건을 확인한다.
- 거래 모니터링과 사건 대기열로 빠르게 이동한다.

### 진입 경로

- 로그인 후 기본 진입 화면
- 좌측 또는 상단 내비게이션의 `대시보드` 메뉴

### 텍스트 와이어프레임

```text
[FDS 대시보드]
┌───────────────────────────────────────────┐
│ 상단: 기간 선택 | 새로고침 | 담당자 표시      │
├───────────────────────────────────────────┤
│ 요약 카드 영역                              │
│  [기간 내 거래 수] [위험 등급별 거래 수]     │
│  [신규 사건 수] [검토 중 사건 수]            │
│  [추가 정보 필요 사건 수] [장기 미처리 사건 수]│
├───────────────────────────────────────────┤
│ 최근 위험 거래 목록 (요약)                   │
├───────────────────────────────────────────┤
│ 담당자별 사건 현황 (후보)                    │
├───────────────────────────────────────────┤
│ 바로가기: [거래 모니터링] [사건 대기열]       │
└───────────────────────────────────────────┘
```

### 주요 정보

- 기간 내 거래 수
- 위험 등급별 거래 수
- 신규 사건 수
- 검토 중 사건 수
- 추가 정보 필요 사건 수
- 장기 미처리 사건 수
- 최근 위험 거래
- 담당자별 사건 현황 후보

집계 기준과 계산식은 이 문서에서 확정하지 않는다.

### 검색·필터·정렬

- 조회 기간 선택
- 위험 등급 필터 후보

### 사용자 행동

- 조회 기간 변경
- 요약 카드 클릭 시 관련 목록 화면으로 이동
- 최근 위험 거래 항목 클릭 시 거래 상세 또는 사건 상세로 이동
- 사건 대기열·거래 모니터링 바로가기 이동

### 상태별 표시

- 로딩 중: 요약 카드와 목록 영역에 로딩 표시
- 조회 결과 없음: 선택한 기간에 데이터가 없음을 표시
- 일부 데이터 조회 실패: 실패한 요약 카드만 오류 표시로 구분하고 나머지는 정상 표시
- 권한 부족: 대시보드 접근 자체가 제한된 경우의 안내 표시

### 오류·빈 데이터 처리

- 요약 집계 실패 시 실패한 항목만 별도 표시하고 나머지 카드는 정상 노출한다.
- 최근 위험 거래가 없으면 빈 상태 문구를 표시한다.

### 권한과 금지 행동

- FDS 분석 담당자만 접근한다.
- 이 화면에서 사건 최종 판정이나 상태 변경을 직접 수행하지 않는다.
- 플랫폼 운영 지표(서비스 Health, AI 비용 등)는 이 화면에 표시하지 않는다.

### 필요한 데이터 후보

- 기간별 거래 집계
- 위험 등급별 거래 집계
- 사건 상태별 집계
- 최근 위험 거래 목록
- 담당자별 사건 집계 후보

### 후속 API 후보

- 거래·사건 요약 집계 조회 API 후보
- 최근 위험 거래 목록 조회 API 후보

### 다른 화면과의 연결

- 거래 모니터링
- 사건 대기열

### 사용자 결정 필요 항목

- 요약 카드 항목의 최종 확정 여부
- 집계 기준 기간의 기본값
- 담당자별 사건 현황 표시 여부

## 2. 거래 모니터링

### 사용자

FDS 분석 담당자

### 화면 목적

- 접수된 거래를 조건별로 조회하고 위험 신호를 확인한다.
- 위험 거래를 사건과 연결해 확인한다.

### 진입 경로

- FDS 대시보드의 바로가기
- 내비게이션의 `거래 모니터링` 메뉴
- 사건 상세의 관련 거래 링크

### 텍스트 와이어프레임

```text
[거래 모니터링]
┌───────────────────────────────────────────┐
│ 검색·필터 영역                              │
│  기간 | 거래 유형 | 위험 등급 | 거래 상태     │
│  고객 식별자 | 계좌 식별자 | transactionId   │
│  사건 생성 여부                             │
├───────────────────────────────────────────┤
│ 거래 목록 테이블                            │
│  시각 | 유형 | 금액 | 발신(마스킹) | 수신(마스킹) │
│  위험점수 | 위험등급 | 주요 Reason Code       │
│  대응 결과 | 연결된 사건                     │
├───────────────────────────────────────────┤
│ 페이지네이션 / 정렬                          │
└───────────────────────────────────────────┘
```

### 주요 정보

- 거래 시각
- 거래 유형
- 금액
- 마스킹된 발신·수신 정보
- 위험 점수
- 위험 등급
- 주요 Reason Code
- 거래 대응 결과
- 연결된 사건

### 검색·필터·정렬

- 기간
- 거래 유형
- 위험 등급
- 거래 상태
- 고객 식별자
- 계좌 식별자
- `transactionId`
- 사건 생성 여부
- 정렬: 거래 시각, 위험 점수 후보

### 사용자 행동

- 조건 검색·필터 적용
- 목록에서 거래 선택 후 상세 확인(별도 상세 화면 또는 확장 영역, 세부 구성은 후속 결정)
- 연결된 사건 클릭 시 사건 상세로 이동
- `transactionId`로 특정 거래 조회

### 상태별 표시

- 로딩 중: 목록 영역 로딩 표시
- 조회 결과 없음: 조건에 해당하는 거래가 없음을 표시
- 일부 데이터 조회 실패: 일부 컬럼(예: Reason Code) 조회 실패 시 해당 셀만 오류 표시
- 권한 부족: 목록 접근이 제한된 경우 안내 표시

### 오류·빈 데이터 처리

- 검색 조건에 맞는 거래가 없으면 빈 상태 문구와 필터 초기화 안내를 제공한다.
- 개인정보는 항상 마스킹된 형태로만 표시하고 원문 노출 기능을 제공하지 않는다.

### 권한과 금지 행동

- FDS 분석 담당자만 접근한다.
- 마스킹 해제나 개인정보 원문 조회 기능을 제공하지 않는다.
- 이 화면에서 거래 상태를 직접 변경하지 않는다.

### 필요한 데이터 후보

- 거래 식별 정보와 마스킹된 발신·수신 정보
- 거래 시각, 유형, 금액
- 위험 점수, 위험 등급, Reason Code
- 거래 대응 결과
- 연결된 사건 식별 정보

### 후속 API 후보

- 거래 목록 조회 API 후보
- 거래 단건 조회 API 후보

### 다른 화면과의 연결

- FDS 대시보드
- 사건 상세

### 사용자 결정 필요 항목

- 거래 상세를 별도 화면으로 분리할지 여부
- 목록에 노출할 마스킹 규칙의 세부 기준

## 3. 사건 대기열

### 사용자

FDS 분석 담당자

### 화면 목적

- 검토가 필요한 사건을 조회하고 우선순위를 판단한다.
- 담당자 배정과 처리 현황을 확인한다.

### 진입 경로

- FDS 대시보드의 바로가기
- 내비게이션의 `사건 대기열` 메뉴

### 텍스트 와이어프레임

```text
[사건 대기열]
┌───────────────────────────────────────────┐
│ 검색·필터 영역                              │
│  사건 상태 | 최종 판정 | 위험 등급 | 담당자   │
│  생성 기간 | 장기 미처리 여부                │
│  caseId | 관련 transactionId               │
├───────────────────────────────────────────┤
│ 사건 목록 테이블                            │
│  사건ID | 생성시각 | 위험등급 | 대표 탐지사유 │
│  사건상태 | 최종판정 | 담당자 | 마지막변경시각│
│  AI 리포트 상태                             │
├───────────────────────────────────────────┤
│ 페이지네이션 / 정렬                          │
└───────────────────────────────────────────┘
```

### 주요 정보

- 사건 ID
- 생성 시각
- 위험 등급
- 대표 탐지 사유
- 현재 사건 상태(`caseStatus`)
- 최종 판정(`finalDisposition`)
- 담당자
- 마지막 변경 시각
- AI 리포트 상태

`caseStatus`는 사건의 현재 업무 진행 상태를 나타내고, `finalDisposition`은 조사 결과를 나타내며 두 정보는 목록에서 서로 다른 컬럼으로 표시한다. 조사가 완료되지 않은 사건은 `finalDisposition`을 비어 있는 값으로 표시한다.

### 검색·필터·정렬

- 사건 상태
- 최종 판정
- 위험 등급
- 담당자
- 생성 기간
- 장기 미처리 여부
- `caseId`
- 관련 `transactionId`
- 정렬: 생성 시각, 위험 등급, 마지막 변경 시각 후보

### 사용자 행동

- 조건 검색·필터 적용
- 목록에서 사건 선택 후 사건 상세로 이동
- 장기 미처리 사건 우선 확인

### 상태별 표시

- 로딩 중: 목록 영역 로딩 표시
- 조회 결과 없음: 조건에 해당하는 사건이 없음을 표시
- 일부 데이터 조회 실패: AI 리포트 상태 등 일부 컬럼 조회 실패 시 해당 셀만 오류 표시
- 권한 부족: 목록 접근이 제한된 경우 안내 표시

### 오류·빈 데이터 처리

- 검색 조건에 맞는 사건이 없으면 빈 상태 문구와 필터 초기화 안내를 제공한다.
- 최종 판정이 아직 없는 사건은 공란 또는 `미판정` 표시로 구분한다.

### 권한과 금지 행동

- FDS 분석 담당자만 접근한다.
- 이 화면에서 최종 판정을 직접 입력하지 않으며, 판정 입력은 사건 상세 화면에서만 수행한다.

### 필요한 데이터 후보

- 사건 목록과 각 사건의 상태·판정·담당자 정보
- 대표 탐지 사유
- AI 리포트 생성 상태

### 후속 API 후보

- 사건 목록 조회 API 후보

### 다른 화면과의 연결

- FDS 대시보드
- 사건 상세

### 사용자 결정 필요 항목

- 장기 미처리 판단 기준
- 담당자 배정 방식(자동/수동)의 확정 여부

## 4. 사건 상세

### 사용자

FDS 분석 담당자

### 화면 목적

- 하나의 사건에 대한 거래, 탐지 근거, 행동, AI 리포트, 메모, 처리 이력을 종합적으로 검토하고 최종 판정을 수행한다.

### 진입 경로

- 사건 대기열의 사건 선택
- FDS 대시보드의 최근 위험 거래 또는 사건 링크
- 거래 모니터링의 연결된 사건 링크

### 텍스트 와이어프레임

```text
[사건 상세: CASE-XXXX]
┌───────────────────────────────────────────┐
│ 사건 요약                                   │
├───────────────────────────────────────────┤
│ 탭 또는 섹션 내비게이션                      │
│  거래정보 | 탐지결과 | 행동타임라인 | 연관거래 │
│  AI 사건 리포트 | 조사 메모 | 사건 처리 | 감사이력│
├───────────────────────────────────────────┤
│ 선택한 섹션의 상세 내용 영역                  │
└───────────────────────────────────────────┘
```

### 주요 정보

아래 하위 영역을 참고한다.

### 검색·필터·정렬

- 감사 이력 영역 내 기간·항목 필터 후보(감사 이력 하위 영역 참고)

### 사용자 행동

- 섹션 간 이동
- 조사 메모 작성
- 사건 상태 변경, 최종 판정 입력, 변경 사유 작성(사건 처리 하위 영역 참고)
- AI 리포트 재생성 요청(가능한 경우)

### 상태별 표시

- 로딩 중: 사건 상세 전체 또는 개별 섹션 로딩 표시
- 조회 결과 없음: 연관 거래·관련 정보가 없는 경우 해당 섹션에 빈 상태 표시
- 일부 데이터 조회 실패: 특정 섹션(예: 외부 위험정보)만 조회 실패로 표시하고 나머지 섹션은 정상 표시
- AI 리포트 생성 중: 생성 진행 상태 표시
- fallback 완료: 템플릿 기반 리포트로 대체 생성되었음을 표시
- AI 리포트 생성 실패: 실패 사유와 재시도 가능 여부 표시
- 다른 사용자의 사건 변경으로 인한 충돌 후보: 저장 시점에 사건이 이미 변경되었음을 알리는 표시 후보
- 권한 부족: 사건 상세 접근 또는 특정 조작(판정 입력 등)이 제한된 경우 안내 표시

### 오류·빈 데이터 처리

- 섹션별로 독립적인 오류 상태를 표시하여 하나의 섹션 실패가 전체 화면을 막지 않도록 한다.
- 저장 실패 시 사용자가 입력한 메모·판정 내용을 보존한다.

### 권한과 금지 행동

- FDS 분석 담당자만 접근한다.
- 이 화면에서 플랫폼 운영 지표(서비스 Health, AI 비용 상세 등)를 표시하지 않는다.
- 생성형 AI가 위험 점수, 최종 판정, 사건 상태를 결정하지 않으며, AI 리포트는 참고 자료로만 사용한다.

### 필요한 데이터 후보

- 하위 영역별 필요 데이터는 각 하위 영역 항목을 참고한다.

### 후속 API 후보

- 사건 상세 조회 API 후보
- 사건 처리(상태·판정) 저장 API 후보
- 조사 메모 등록 API 후보
- AI 리포트 재생성 요청 API 후보

### 다른 화면과의 연결

- 사건 대기열
- 거래 모니터링
- Rule 조회
- 감사 로그

### 사용자 결정 필요 항목

- 허용되는 사건 상태 전이(후속 상태 전이 문서에서 확정)
- 동시 수정 충돌 처리 방식
- AI 리포트 재생성 허용 횟수와 조건

### 4.1 사건 요약

- 마지막 변경 시각

`caseStatus`와 `finalDisposition`은 각각 별도 항목으로 표시하며 하나의 값으로 통합하지 않는다.

## 5. Rule 조회

### 사용자

FDS 분석 담당자

### 화면 목적

- 현재 적용 중인 탐지 Rule의 정의와 상태를 조회한다.

### 진입 경로

- 사건 상세의 탐지 결과 영역에서 Rule 상세 확인
- 내비게이션의 `Rule 조회` 메뉴

### 텍스트 와이어프레임

```text
[Rule 조회]
┌───────────────────────────────────────────┐
│ Rule 목록 테이블                            │
│  Rule ID | 이름 | 설명 | 가중치              │
│  버전 | 활성 상태 | 적용일                   │
└───────────────────────────────────────────┘
```

### 주요 정보

- Rule ID
- 이름
- 설명
- 가중치
- 버전
- 활성 상태
- 적용일

### 검색·필터·정렬

- Rule 이름 또는 ID 검색 후보
- 활성 상태 필터 후보

### 사용자 행동

- Rule 목록 조회
- 개별 Rule 상세 확인(조회 전용)

### 상태별 표시

- 로딩 중
- 조회 결과 없음
- 일부 데이터 조회 실패
- 권한 부족

### 오류·빈 데이터 처리

- Rule 목록이 없으면 빈 상태 문구를 표시한다.

### 권한과 금지 행동

- 이 화면은 초기에는 조회 전용이며 Rule 수정 기능을 제공하지 않는다.
- Rule 수정 기능 도입 여부는 이 문서에서 확정하지 않는다.

### 필요한 데이터 후보

- Rule 정의와 버전 이력

### 후속 API 후보

- Rule 목록 조회 API 후보
- Rule 단건 조회 API 후보

### 다른 화면과의 연결

- 사건 상세(탐지 결과 영역)

### 사용자 결정 필요 항목

- Rule 수정·관리 기능의 도입 여부와 시점

## 6. 감사 로그

### 사용자

FDS 분석 담당자

### 화면 목적

- 거래·사건과 관련된 변경 이력을 조회한다.

### 진입 경로

- 사건 상세의 감사 이력 영역에서 확장 이동
- 내비게이션의 `감사 로그` 메뉴

### 텍스트 와이어프레임

```text
[감사 로그]
┌───────────────────────────────────────────┐
│ 검색 영역                                   │
│  기간 | 사용자 | 변경 대상 유형              │
│  transactionId | caseId | 변경 작업         │
├───────────────────────────────────────────┤
│ 감사 로그 목록 테이블                        │
│  변경시각 | 변경사용자 | 변경대상 | 이전값    │
│  변경후값 | 변경사유 | 관련 거래·사건        │
└───────────────────────────────────────────┘
```

### 주요 정보

- 변경 시각
- 변경 사용자
- 변경 대상
- 이전 값
- 변경 후 값
- 변경 사유
- 관련 거래·사건

### 검색·필터·정렬

- 기간
- 사용자
- 변경 대상 유형
- `transactionId`
- `caseId`
- 변경 작업

### 사용자 행동

- 조건 검색
- 목록에서 항목 선택 후 관련 거래·사건으로 이동

### 상태별 표시

- 로딩 중
- 조회 결과 없음
- 일부 데이터 조회 실패
- 권한 부족

### 오류·빈 데이터 처리

- 검색 조건에 맞는 이력이 없으면 빈 상태 문구를 표시한다.

### 권한과 금지 행동

- FDS 분석 담당자만 접근한다.
- 이 화면에서 감사 로그 내용을 수정·삭제하지 않는다.

### 필요한 데이터 후보

- 거래·사건 관련 변경 이력

### 후속 API 후보

- 감사 로그 조회 API 후보

### 다른 화면과의 연결

- 사건 상세

### 사용자 결정 필요 항목

- 감사 로그 보존 기간과 접근 범위
