# FinGuardOps 플랫폼 운영 화면 와이어프레임

## 0. 문서 경계

- 본 문서는 플랫폼·클라우드 운영자의 서비스·성능·장애·AI 비용 화면을 정의한다.
- 사건의 최종 판정은 `docs/01-requirements/fds-screen-wireframes.md`의 FDS 분석 화면에서 수행한다.
- 기술 메트릭 상세 시계열은 Grafana에서 제공하며, 이 문서의 React 화면은 업무 영향과 운영 조치 요약에 집중한다.
- 구체적인 메트릭 이름과 임계값은 후속 문서에서 확정한다.
- 이 문서는 요구사항 단계의 텍스트 와이어프레임이며, 구체적인 API 경로, DTO, Entity, DB 컬럼, 상태 전이와 픽셀 단위 디자인은 다루지 않는다.
- 참고 문서: `docs/01-requirements/platform-operation-requirements.md`, `docs/07-decisions/ADR-001-finguardops-positioning.md`

## 1. 플랫폼 운영 대시보드

### 사용자

플랫폼·클라우드 운영자

### 화면 목적

- 서비스 전반의 운영 상태를 한 화면에서 요약해서 확인한다.
- 이상 징후를 조기에 발견하고 상세 화면 또는 Grafana로 이동한다.

### 진입 경로

- 로그인 후 운영자 기본 진입 화면
- 내비게이션의 `운영 대시보드` 메뉴

### 텍스트 와이어프레임

```text
[플랫폼 운영 대시보드]
┌───────────────────────────────────────────┐
│ 상단: 새로고침 | 마지막 갱신 시각            │
├───────────────────────────────────────────┤
│ 서비스별 Health 요약 카드                    │
│  [Spring Boot] [FastAPI] [PostgreSQL]       │
│  [Redis] [Kafka] [External Risk Mock] [LLM] │
├───────────────────────────────────────────┤
│ 현재 배포 버전 요약                          │
├───────────────────────────────────────────┤
│ 주요 오류율·지연시간 상태 요약                │
├───────────────────────────────────────────┤
│ DB Connection Pool 상태 | Kafka Consumer Lag │
├───────────────────────────────────────────┤
│ LLM 호출량·비용 요약 | fallback 비율          │
├───────────────────────────────────────────┤
│ 최근 장애 목록 | 최근 배포 목록               │
├───────────────────────────────────────────┤
│ 운영 알림 목록 (후보)                        │
└───────────────────────────────────────────┘
```

### 주요 정보

- 서비스별 Health 요약
- 현재 배포 버전
- 주요 오류율·지연시간 상태
- DB Connection Pool 상태
- Kafka Consumer Lag
- LLM 호출량과 비용
- fallback 비율
- 최근 장애
- 최근 배포
- 운영 알림 후보

### 검색·필터·정렬

- 조회 기간 선택 후보
- 서비스별 필터 후보

### 사용자 행동

- 요약 카드 클릭 시 서비스 상태, AI 운영·비용, 장애 이력, 배포 이력 화면으로 이동
- Grafana 상세 보기로 이동(연결 링크)
- 운영 알림 확인

### 상태별 표시

이 화면은 항목별로 다음 상태를 구분해서 표시한다.

- 정상
- 경고
- 장애
- 상태 확인 불가
- 수집 전
- 미도입
- 데이터 없음
- 일부 메트릭 수집 실패
- 비용 데이터 지연
- Grafana 연결 불가
- 권한 부족

`미도입`(예: Kafka처럼 아직 도입하지 않은 대상), `수집 전`(연동은 있으나 아직 지표 수집을 시작하지 않은 상태), `데이터 없음`(수집은 되지만 해당 기간에 값이 없는 상태), `상태 확인 불가`(수집 경로 자체의 장애로 판단이 불가능한 상태)를 서로 다른 표시로 구분한다.

### 오류·빈 데이터 처리

- 특정 요약 카드만 조회 실패하면 해당 카드만 오류 표시로 구분하고 나머지 카드는 정상 표시한다.
- Kafka처럼 아직 도입하지 않은 항목은 오류가 아니라 `미도입`으로 표시한다.

### 권한과 금지 행동

- 플랫폼·클라우드 운영자만 접근한다.
- 이 화면에서 사건의 최종 판정(`NORMAL`, `FALSE_POSITIVE`, `CONFIRMED_FRAUD`)을 수행하지 않는다.
- Prometheus 메트릭을 그대로 복제한 시계열 그래프를 이 화면에 구현하지 않으며, 상세 시계열은 Grafana 링크로 연결한다.

### 필요한 데이터 후보

- 서비스별 Health 및 마지막 정상 확인 시각
- 배포 버전 이력
- 오류율·지연시간 요약 지표
- DB Connection Pool, Kafka Consumer Lag 요약
- LLM 호출량·비용·fallback 요약
- 최근 장애·배포 요약

### 후속 API 후보

- 운영 대시보드 요약 조회 API 후보

### 다른 화면과의 연결

- 서비스 상태
- AI 운영·비용
- 장애 이력
- 배포 이력
- Grafana(외부 연결)

### 사용자 결정 필요 항목

- 요약 카드 구성과 우선순위
- 알림 표시 방식과 채널

## 2. 서비스 상태

### 텍스트 와이어프레임

```text
[서비스 상태]
┌───────────────────────────────────────────┐
│ 운영 대상 목록                              │

│  배포 버전 | 관련 장애                       │
│  Grafana 상세 보기 링크 (후보)               │

```

표시 정보 후보:

- 현재 상태
- 마지막 정상 확인 시각

- 최근 응답시간 요약

- 관련 장애 클릭 시 장애 이력으로 이동
- Grafana 상세 보기 링크로 이동

### 상태별 표시

- 정상
- 경고
- 장애
- 상태 확인 불가
- 수집 전
- 미도입
- 데이터 없음
- 일부 메트릭 수집 실패
- Grafana 연결 불가
- 권한 부족

- Kafka와 같이 아직 도입하지 않은 대상은 `미도입` 상태로 표시하고 오류로 취급하지 않는다.
- 상태 확인 자체가 실패하면 `상태 확인 불가`로 별도 표시한다.

### 후속 API 후보

## 4. 장애 이력

### 사용자

플랫폼·클라우드 운영자

### 화면 목적

- 발생한 장애의 현상, 원인, 대응과 재발 방지 내용을 조회한다.

### 진입 경로

- 플랫폼 운영 대시보드의 최근 장애 목록 클릭
- 서비스 상태의 관련 장애 클릭
- 내비게이션의 `장애 이력` 메뉴

### 텍스트 와이어프레임

```text
[장애 이력]
┌───────────────────────────────────────────┐
│ 검색 영역                                   │
│  기간 | 영향 서비스 | 장애 상태              │
├───────────────────────────────────────────┤
│ 장애 목록                                   │
│  발생·종료 시각 | 장애 상태 | 영향 서비스     │
│  영향 기능 | 관련 배포 버전                  │
├───────────────────────────────────────────┤
│ 장애 상세                                   │
│  현상 → 탐지 지표 → 원인                     │
│  → 임시 대응 → 구조적 해결 → 재발 방지        │
│  담당자 | 관련 식별자                        │
└───────────────────────────────────────────┘
```

### 주요 정보

- 발생·종료 시각
- 장애 상태
- 영향 서비스
- 영향 기능
- 관련 배포 버전
- 탐지 지표
- 임시 대응
- 원인
- 구조적 해결
- 재발 방지
- 담당자
- 관련 식별자

장애 상세는 다음 기록 구조를 사용한다.

```text
현상 → 탐지 지표 → 원인 → 임시 대응 → 구조적 해결 → 재발 방지
```

### 검색·필터·정렬

- 기간
- 영향 서비스
- 장애 상태
- 관련 배포 버전 후보

### 사용자 행동

- 조건 검색
- 장애 목록에서 항목 선택 후 상세 확인
- 관련 배포로 이동

### 상태별 표시

- 정상(장애 없음)
- 경고
- 장애(진행 중)
- 장애(종료)
- 데이터 없음
- 수집 전
- 권한 부족

### 오류·빈 데이터 처리

- 조건에 맞는 장애가 없으면 빈 상태 문구를 표시한다.
- 원인이 아직 확인되지 않은 장애는 `원인 확인 중`으로 구분해서 표시하고 확정된 원인처럼 표시하지 않는다.

### 권한과 금지 행동

- 플랫폼·클라우드 운영자만 접근한다.
- 이 화면에서 FDS 사건의 최종 판정을 수행하지 않는다.
- `ServiceIncident` Entity 구조는 이 화면에서 확정하지 않는다.

### 필요한 데이터 후보

- 장애 발생·종료 시각과 상태
- 영향 서비스·기능
- 탐지 지표, 원인, 임시 대응, 구조적 해결, 재발 방지
- 관련 배포 버전과 식별자(`traceId`, `transactionId`, `caseId`, `aiRequestId` 등)

### 후속 API 후보

- 장애 이력 목록 조회 API 후보
- 장애 이력 상세 조회 API 후보

### 다른 화면과의 연결

- 플랫폼 운영 대시보드
- 서비스 상태
- 배포 이력

### 사용자 결정 필요 항목

- 장애 등급 기준
- 장애 이력 저장 방식과 보존 기간

## 5. 배포 이력

### 사용자

플랫폼·클라우드 운영자

### 화면 목적

- 서비스별 배포 이력과 배포 전후 영향을 확인한다.

### 진입 경로

- 플랫폼 운영 대시보드의 최근 배포 목록 클릭
- 서비스 상태의 배포 버전 클릭
- 내비게이션의 `배포 이력` 메뉴

### 텍스트 와이어프레임

```text
[배포 이력]
┌───────────────────────────────────────────┐
│ 검색 영역                                   │
│  기간 | 대상 환경 | 배포 상태                │
├───────────────────────────────────────────┤
│ 배포 목록                                   │
│  배포시각 | 버전 | 대상환경 | 배포상태        │
│  수행주체 | 관련 Commit·PR                  │
│  배포 후 오류율·지연시간 변화 (후보)          │
│  Rollback 여부                             │
└───────────────────────────────────────────┘
```

### 주요 정보

- 배포 시각
- 버전
- 대상 환경
- 배포 상태
- 수행 주체
- 관련 Commit·PR
- 배포 후 오류율·지연시간 변화 후보
- Rollback 여부

### 검색·필터·정렬

- 기간
- 대상 환경
- 배포 상태
- 버전 후보

### 사용자 행동

- 조건 검색
- 배포 항목 선택 후 상세 확인
- 관련 장애로 이동(배포 후 이상 징후가 있는 경우)

### 상태별 표시

- 정상(배포 완료)
- 경고(배포 후 이상 징후)
- 장애(배포 관련 장애)
- Rollback 완료
- 데이터 없음
- 수집 전
- 권한 부족

### 오류·빈 데이터 처리

- 조건에 맞는 배포 이력이 없으면 빈 상태 문구를 표시한다.
- 배포 후 지표 비교 데이터가 아직 없으면 `데이터 없음` 또는 `수집 전`으로 구분해서 표시한다.

### 권한과 금지 행동

- 플랫폼·클라우드 운영자만 접근한다.
- 이 화면에서 실제 배포나 Rollback을 직접 실행하지 않으며, 이미 수행된 배포 이력만 조회한다.
- `DeploymentRecord` Entity와 실제 CI/CD 구현은 이 화면에서 확정하지 않는다.

### 필요한 데이터 후보

- 배포 시각, 버전, 대상 환경, 상태
- 수행 주체와 관련 Commit·PR
- 배포 전후 오류율·지연시간 비교 데이터
- Rollback 여부

### 후속 API 후보

- 배포 이력 목록 조회 API 후보
- 배포 이력 상세 조회 API 후보

### 다른 화면과의 연결

- 플랫폼 운영 대시보드
- 서비스 상태
- 장애 이력

### 사용자 결정 필요 항목

- 배포 이력 저장 방식
- 배포 후 이상 판단 기준과 Rollback 조건
